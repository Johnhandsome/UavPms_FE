# MF02 v2.0 — FE Specification
## Create & Assign Inspection Mission

## 1. Version History

| Version | Change |
|---|---|
| v1.0.x | Create Mission flow independently selected Region, Line, Towers/Assets, UAV and Inspector. |
| **v2.0** | Renumbered/refactored to MF02. The FE now **consumes a READY Pre-MissionAssessment from MF01**, reviews its scope, selects final eligible personnel/UAV, performs final backend revalidation, creates the mission and supports Inspector Accept/Postpone. |

## 2. FE Goal

MF02 converts a valid READY assessment into an actual inspection mission.

MF02 must not repeat the entire MF01 workflow.

Key rule:

> Load → review → confirm → select final resources → create.

Do **not** force the Manager to re-select Region/Line/Towers from zero when the assessment already contains the evaluated scope.

## 3. Primary Actors

- **Mission Manager**: Phân công nhân sự theo 3 vai trò (Inspector, Analyst, Technician), thiết lập UAV và hạn chót xác nhận (`confirmationDeadline`), điều phối xử lý khi có nhân sự hoãn.
- **Inspector / Pilot**: Nhận nhiệm vụ, kiểm tra thông số hành lang bay/UAV, xác nhận sẵn sàng bay (Accept) hoặc xin hoãn (Postpone).
- **Analyst**: Nhận nhiệm vụ, kiểm tra chỉ tiêu dữ liệu hình ảnh/AI, cấu hình loại khuyết tật cần phân tích, xác nhận tiếp nhận phân tích hoặc xin hoãn.
- **Technician**: Nhận nhiệm vụ, kiểm định tình trạng kỹ thuật thực tế của UAV/pin/trạm mặt đất, xác nhận kỹ thuật đạt chuẩn sẵn sàng cất cánh hoặc xin hoãn.
- **Backend & SignalR Hub**: Nguồn dữ liệu kiểm định quyền hạn, điều phối sự kiện thời gian thực tới từng nhóm vai trò, kiểm soát trạng thái tổng hợp (Aggregate Status) và cảnh báo quá hạn.
- **Notification Subsystem**: Đẩy thông báo đa kênh (In-app, SMS, Email) tới tất cả các thành viên được phân công.

## 4. Main User Flow

```text
Open READY Assessment (MF01)
        ↓
Review Scope + Planned Window
        ↓
Confirm Mission Assets
        ↓
Assign Required Personnel for 3 Roles:
  ├── Inspector / Pilot (≥ 1 người)
  ├── Analyst           (≥ 1 người)
  └── Technician        (≥ 1 người)
        ↓
Select Eligible READY UAV
        ↓
Enter / Confirm Mission Info & Confirmation Deadline
        ↓
Final Backend Revalidation
        ↓
Create Mission (Status: PENDING_CONFIRMATION)
        ↓
Dispatch Notifications & SignalR Broadcast to 3 Roles
        ↓
Multi-Role Confirmation Stage (Chờ đủ 3 Roles):
  ├── Inspector Review  ──→ [Accept / Postpone]
  ├── Analyst Review    ──→ [Accept / Postpone]
  └── Technician Review ──→ [Accept / Postpone]
        ↓
Status Evaluation:
  ├── TẤT CẢ 3 Roles đều Accept  ──→ Mission Status = CONFIRMED (Sẵn sàng triển khai MF03)
  └── BẤT KỲ Role nào Postpone  ──→ Báo động Manager ──→ Reassign (Đổi người) HOẶC Postpone nhiệm vụ
```

## 5. Entry Conditions

MF02 receives an `assessmentId`.

Before rendering an actionable create page:
- assessment exists;
- status = READY;
- not expired;
- not already consumed;
- current user has create permission.

If invalid, show a dedicated state and do not render a misleading active Create button.

## 6. Required Screens

### 6.1 Create Mission from Assessment

Recommended page structure:

```text
┌────────────────────────────────────────────────────────────┐
│ Create Inspection Mission       Assessment #...   READY    │
├────────────────────────────────────────────────────────────┤
│ Scope Summary                                               │
│ Region → Line → 12 Towers                    [View on GIS]  │
├────────────────────────────────────────────────────────────┤
│ Mission Information                                        │
│ Name | Planned Start | Planned End | Priority | Deadline   │
├────────────────────────────────────────────────────────────┤
│ Personnel Assignment (Required ≥ 1 per role: 3/3 Fulfilled)│
│ [1. Inspector / Pilot]                                     │
│   ● Inspector B (Available | Active | Scope OK | Qual OK)  │
│ [2. Data / AI Analyst]                                     │
│   ● Analyst C   (Available | Active | Scope OK | Qual OK)  │
│ [3. Hardware Technician]                                   │
│   ● Technician D(Available | Active | Scope OK | Qual OK)  │
├────────────────────────────────────────────────────────────┤

│ ● UAV-03  AVAILABLE | HEALTHY | inspection valid            │
│ ○ UAV-07  AVAILABLE | WARNING | policy result ...           │
├────────────────────────────────────────────────────────────┤
```

### 6.2 Scope Review

Show:
- Region
- Line / Line Segment
- Towers / Assets
- count
- optional assessment geometry
- GIS preview

Scope is initially read from MF01.

If product allows material scope edits:
- clearly warn that changes may invalidate readiness;
- backend decides whether `REASSESSMENT_REQUIRED`;
- never silently expand scope.

### 6.3 Mission Information

Fields:
- Mission Name
- Description / Notes
- Planned Start
- Planned End
- Priority
- Confirmation Deadline (`confirmationDeadline`: thời hạn chót để cả 3 role phản hồi trước khi bị đánh dấu OVERDUE)
- Mission Type where applicable

Validation:
- required name;
- end > start;
- at least one MissionAsset;
- confirmationDeadline must be before plannedStart and after current time;
- server validation messages displayed next to relevant field.

### 6.4 Personnel Assignment (3 Roles Mandate)

Mỗi nhiệm vụ kiểm tra bay lưới điện bắt buộc phải cấu hình và phân công đủ **tối thiểu 3 vai trò**:
1. **Inspector / Pilot** (≥ 1 người)
2. **Analyst** (≥ 1 người)
3. **Technician** (≥ 1 người)

Manager có thể cấu hình số lượng cho từng role (ví dụ: cần 2 Inspector cho tuyến dài, 1 Analyst, 1 Technician).

#### Bộ tiêu chí lọc ứng viên theo 5 điều kiện (Logic AND):
Chỉ những ứng viên thỏa mãn đồng thời 5 tiêu chuẩn sau mới được hiển thị trong danh sách lựa chọn:
1. **Eligible**: Không bị kỷ luật, đủ điều kiện an toàn, có chứng chỉ hành nghề phù hợp.
2. **AND Active**: Tài khoản đang hoạt động, không nghỉ ca/nghỉ phép.
3. **AND Within Region/Scope**: Thuộc đúng Đơn vị quản lý / Chi nhánh / Đội truyền tải của tuyến khảo sát.
4. **AND Available during proposed time**: Không bị trùng lịch làm việc với nhiệm vụ khác trong khoảng `plannedStart` → `plannedEnd`.
5. **AND Has required role/qualification**: Có đúng chuyên môn/chứng chỉ được hệ thống cấp phép cho vai trò tương ứng (Inspector, Analyst, Technician).

Validation phân công:
- Khóa nút [Create Mission] nếu thiếu bất kỳ vai trò nào trong 3 vai trò trên (< 1 người/role).
- Cảnh báo trực quan nếu số lượng được chọn nhỏ hơn định mức quy định của loại hình nhiệm vụ.

### 6.5 UAV Assignment

Display:
- UAV
- Operational Status
- Technical Health
- Technical Inspection validity
- Current conflict
- eligibility

Do not run Betaflight/FC technical inspection here.

MF02 only revalidates current technical/operational state through backend.

### 6.6 Final Review

Before create, show compact summary:
- assessment reference;
- scope;
- schedule;
- personnel assignment (đủ 3 role);
- UAV;
- warnings.

Create button:
- disabled during submit;
- protected from double click;
- uses idempotency behavior supported by backend.

### 6.7 Creation Result & Multi-Role Dispatch

After successful create:
- Mission chuyển trạng thái `PENDING_CONFIRMATION`;
- Backend kích hoạt Background Job theo dõi hạn chót xác nhận (`confirmationDeadline`);
- Hệ thống gửi thông báo đồng thời (In-app, SMS, Email) và phát sóng SignalR event `MissionDispatched` tới **toàn bộ các nhân sự thuộc cả 3 roles**;
- Route to Mission Detail;
- Hiển thị danh sách các phân công với trạng thái `PENDING` của từng cá nhân.

### 6.8 Multi-Role Confirmation Console (Accept / Postpone)

Từng nhân sự trong 3 vai trò (Inspector, Analyst, Technician) truy cập vào màn hình tiếp nhận nhiệm vụ (Console xác nhận chuyên biệt hoặc giao diện `/missions/:id/confirmation`):

1. **Inspector / Pilot Review**:
   - Kiểm tra hành lang lưới điện, tọa độ cột, vùng đệm an toàn GIS, trạm thời tiết, thông số kỹ thuật UAV được bàn giao.
   - Thao tác: **Accept Mission** hoặc **Postpone Mission** (kèm lý do).
2. **Analyst Review**:
   - Kiểm tra danh mục hạng mục thiết bị trên cột (cách điện, mối nối, phụ kiện), danh sách loại khuyết tật dự kiến cần AI phân tích, yêu cầu độ phân giải hình ảnh/video.
   - Thao tác: **Accept Mission** hoặc **Postpone Mission** (kèm lý do).
3. **Technician Review**:
   - Kiểm tra hiện trạng vật lý và pin của UAV, nhật ký kiểm tra kỹ thuật gần nhất (BIST/MSP), thiết bị phụ trợ (bộ điều khiển, trạm sạc, ăng-ten).
   - Thao tác: **Accept Mission** hoặc **Postpone Mission** (kèm lý do).

Mỗi nhân sự chỉ được quyền Accept hoặc Postpone trên chính `assignmentId` của bản thân.

### 6.9 Postpone Dialog & Reassignment Handling

Khi một thành viên bấm **Postpone**:
- Bắt buộc nhập lý do chi tiết (`postponeReason`).
- Phân công của thành viên đó chuyển sang `POSTPONED`.
- Trạng thái nhiệm vụ chuyển sang `POSTPONED` hoặc cờ cảnh báo `NEED_REASSIGNMENT`.
- Hệ thống lập tức bắn SignalR event `MissionPostponed` tới Manager kèm thông tin: `actorRole`, `actorName`, `reason`.
- **Manager Action trên trang Mission Detail**:
  - **Reassign Role (Đổi nhân sự)**: Manager mở modal chọn ứng viên thay thế khác trong nhóm ứng viên hợp lệ của vai trò đó mà không cần hủy toàn bộ nhiệm vụ.
  - **Reschedule / Postpone Mission**: Dời khung giờ nhiệm vụ sang thời điểm khác nếu không có nhân sự thay thế.
  - **Cancel Mission**: Hủy nhiệm vụ kèm lý do nếu không thể thu xếp nhân lực.

## 7. State Model

Mission:
`DRAFT → PENDING_CONFIRMATION → CONFIRMED | POSTPONED | SUSPENDED | CANCELLED`

Assignment (từng thành viên):
`PENDING → ACCEPTED | POSTPONED | REPLACED | CANCELLED`

### Aggregate Confirmation Logic (Quy tắc tổng hợp):
- **PENDING_CONFIRMATION**: Nhiệm vụ mới ban hành, đang đợi phản hồi từ các thành viên.
- **CONFIRMED**: Khi và chỉ khi **100% các vai trò bắt buộc (Inspector, Analyst, Technician)** đều đã phản hồi `ACCEPTED`. Lúc này nhiệm vụ mới chính thức hợp lệ để chuẩn bị bay thực địa (MF03).
- **POSTPONED**: Khi có **ít nhất 01 thành viên** trong 3 role gửi yêu cầu `POSTPONED`.
- **OVERDUE**: Khi đã qua thời điểm `confirmationDeadline` mà vẫn còn ít nhất 01 thành viên chưa phản hồi (vẫn ở `PENDING`).

Frontend tuyệt đối không tự ý chuyển Mission sang `CONFIRMED` nếu chỉ có 1 hoặc 2 role xác nhận.

## 8. Final Revalidation UX

MF01 readiness is a snapshot. MF02 can fail at commit because resources changed.

Handle explicit backend conflicts:

- `ASSESSMENT_EXPIRED`
- `ASSESSMENT_ALREADY_CONSUMED`
- `REASSESSMENT_REQUIRED`
- `PERSONNEL_UNAVAILABLE`
- `RESOURCE_SCHEDULE_CONFLICT`
- `DRONE_UNAVAILABLE`
- `DRONE_INSPECTION_EXPIRED`
- `DRONE_NOT_ELIGIBLE`
- `CONCURRENT_UPDATE`

UX response:
- explain the exact resource/problem;
- preserve safe user-entered mission metadata;
- refresh candidate/resource state;
- redirect to MF01 only when reassessment is actually required.

## 9. API Integration Rules

Expected surface:

```text
POST /api/v2/pre-mission-assessments/{assessmentId}/create-mission  (hoặc POST /api/v2/missions)
  Payload: {
    assessmentId: string,
    title: string,
    description?: string,
    plannedStart: string,
    plannedEnd: string,
    confirmationDeadline: string,
    droneIds: string[],
    priority?: string,
    assignments: [ // Backend hỗ trợ alias "personnel" hoặc "assignments"
      { userId: string, role: "INSPECTOR", isRequired: true },
      { userId: string, role: "ANALYST", isRequired: true },
      { userId: string, role: "TECHNICIAN", isRequired: true }
    ],
    idempotencyKey?: string
  }

GET  /api/v2/missions/{missionId}
PATCH /api/v2/missions/{missionId}

POST /api/v2/missions/{missionId}/assignments/accept  (hoặc .../assignments/{assignmentId}/accept)
POST /api/v2/missions/{missionId}/assignments/postpone (hoặc .../assignments/{assignmentId}/postpone)
  Payload: { reason: string }

POST /api/v2/missions/{missionId}/assignments/{assignmentId}/reassign
  Payload: { newUserId: string, reassignReason?: string }

GET /api/v2/pre-mission-assessments/{assessmentId}/create-mission-context
```

FE must not trust cached candidate state as current authority. Backend performs final validation.

## 10. Concurrency / Idempotency

- Disable Create while request is active.
- Preserve idempotency key for retry of the same create attempt.
- HTTP 409 never triggers blind automatic resubmit.
- On stale mission during user review, refresh latest mission before response.
- Show “mission updated” state if Manager changed data after page load.

## 11. Notifications & Realtime (SignalR)

SignalR Hub (`/hubs/notifications`):
- Broadcast to group `mission_{missionId}` khi có bất kỳ sự kiện vòng đời nào.
- Sự kiện `MissionConfirmed`: Gửi kèm `assignmentId`, `actorRole`, `actorName`, và `allConfirmed` flag.
- Sự kiện `MissionPostponed`: Gửi kèm `assignmentId`, `actorRole`, `actorName`, `reason`.
- Sự kiện `MissionConfirmationOverdue`: Tự động bắn khi có role trễ hạn xác nhận.
- Cả Manager, Inspector, Analyst, Technician đều tham gia nhóm `mission_{missionId}` để nhận đồng bộ thời gian thực hai chiều.

Notification failure is not equivalent to mission creation failure.

## 12. Permissions

- Only authorized Manager can create missions, assign personnel, reassign members, or suspend/cancel missions.
- Assigned Inspector, Analyst, Technician can only view their own assignment and perform Accept/Postpone on their own assignment.
- Frontend visibility is convenience only; backend authorization remains authoritative.

## 13. Loading / Empty / Error States

Required:
- loading assessment context;
- assessment unavailable/expired/consumed;
- no eligible personnel for one or more of the 3 required roles;
- no eligible UAV;
- resource changed;
- validation error;
- 403;
- 409;
- 5xx/network failure.

## 14. FE Acceptance Criteria

- MF02 requires READY assessment.
- Scope is loaded from MF01 rather than redundantly rebuilt.
- Personnel assignment strictly requires selecting at least 3 roles: Inspector, Analyst, and Technician (each ≥ 1) meeting the 5-point criteria.
- Create Mission button is disabled if any of the 3 roles is missing.
- Confirmation workflow enforces waiting for confirmation from all 3 roles before mission status transitions to `CONFIRMED`.
- If any role postpones, Manager is notified via SignalR in real-time and can reassign that specific role.
- Role-specific confirmation views or dialogs exist for Inspector, Analyst, and Technician.
- All primary screens follow the shared UAV-PMS design system.
